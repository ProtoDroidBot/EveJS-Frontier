## What differs from 3640684

This sandbox profile is **2884873**, not the 2898485 number on its parent
folder. It contains 531 `frontier/` members. Unlike the co-located release,
it packages `frontier/heat_system/`, `frontier/lagrange_occupancy/` and common
signature/scan definitions. Main beta direct assignments for disabling scanning
and hiding the classic map are absent. That absence does not by itself enable
scanning or establish a working server workflow.

`frontier/heat_system/beta.pyc:4` queries global `heat_enabled` with a compiled
true fallback. `frontier/heat_system/client/temperature_service.pyc:71/74/77`
reads base temperature, current temperature and time scale through the state
manager. `frontier/lagrange_occupancy/client/lagrange_occupancy_svc.pyc:19`
uses `lagrangeOccupancyMgr`, exposing add/remove/get/is-occupied and
system/planet/owner/type queries. Its occupancy service lacks the later
repository/session-invalidation layer present in 2973163.

Online/offline assembly remains the signed `encryptedWallet` / `send_meta_tx`
path. Cryptocurrency exchange methods at
`frontier/web3/client/cryptocurrency_svc.pyc:26/44/50/53` use the legacy
`encryptionWalletService` integration, rather than the newer public
token-exchange descriptor family.

All four audited Era5/early-Era6 profiles lack the newer `frontier/creation/`,
`frontier/docking_point/`, `frontier/navigation/`, `frontier/character/`
progression family and generated Universe-v1 schema metadata present in 3640684.
Their older `crdata`, manufacturing, smart-assembly, base-building and HUD code
must be assessed on its own interfaces. Identical MachoNet 489 does not establish
native movement, CRData, gateway or durable-world compatibility.

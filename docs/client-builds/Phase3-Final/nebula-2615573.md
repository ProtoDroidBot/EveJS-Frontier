## Meaningful client differences

This ALPHA_RELEASE snapshot still uses EVE/Python 2.7, but its client
organization contains the Frontier HUD, smart deployables and public-gateway
web3 integration. It differs substantially from the 3640684 cycle-7 client.

- `frontier/smart_deployable/client/services/smart_storage_unit_svc.pyj:27`
  creates a chain client from `publicGatewaySvc`. `online:31` and `offline:41`
  ask `encryptedWallet` to create online/offline meta-transactions and send
  them with success/failure callbacks. This records the archived dependency
  and workflow; no transaction was submitted.
- `frontier/web3/client/cryptocurrency_svc.pyj` packages a public-gateway and
  encrypted-wallet balance workflow rather than Phase2's `frontier/chain/`
  family. The different package layout must not be treated as the same API
  implementation just because some public request messages remain equal.
- Direct assignments in `frontier/beta.pyj` set
  `FRONTIER_BETA_CLIENT_RANGE_BASED_OCCLUSION=True`, compared with False in
  3640684. Target-only constants include `FRONTIER_BETA_DISABLE_SCANNING=True`,
  `FRONTIER_BETA_SHOW_ID_BARCODE=True` and legacy map/structure/UI hiding
  flags. These are compiled flags, not a live activation measurement.
- The classic constructables service still references
  `stationConstructableManager` and `industryManager2` for blueprint/job
  operations; their payload compatibility was not established by inspection.

The target has 113 `frontier/hud/`, 39 `frontier/crdata/`, 37
`frontier/smart_deployable/`, 34 `frontier/industry/` and 28
`frontier/overview/` members. Newer navigation, docking-point, skillshot,
status-effect, Creation and signatures/scanning package families are absent
under those module names. Legacy equivalents elsewhere were not ruled out.

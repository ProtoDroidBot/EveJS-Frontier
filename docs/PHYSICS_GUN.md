# Physics Gun (99999)

Physics Gun is a local copy of Cutting Laser (95317) for Frontier build 3502403. The DatabaseCreator copies the source type and complete type Dogma entry, changes the display name to `Physics Gun`, and adds a `creationModules` adapter with generic weapon behavior on weapon hardpoints. It rejects an upstream SDE collision on type ID 99999.

The server registers 99999 as a laser turret held beam. It uses Cutting Laser's 250 ms spool, effect 12887, charge attributes, and authoritative first collision trace. A hit on eligible dungeon scenery, an asteroid (including a mineable asteroid), or an authored collision prop detaches it into a persistent world object and starts a physics tether. Physics Gun hits do not mine or deal combat damage. The staged client overlays the native type, Dogma, and Creation module dictionaries; localization message IDs 99999001 and 99999002 supply the Physics Gun name and description; the SkillShot profile points to Cutting Laser's held beam profile. The Creation module overlay inherits Cutting Laser's FSD-generated `exterior` placement object so the client recognizes Physics Gun as a weapon receiver attachment; replacing that object with a plain namespace makes it invisible to the fitting UI.

While the beam is held, the tether point follows ship movement and aim even when the reticle is unchanged. The detached ball follows under swept collision and acceleration rules, with the Feral Drone style scan effect on the moved object. The carrier ship is excluded from collision with its held prop; other collisions still settle it. An initial overlap with scenery can clear when the prop moves outward. Client GotoPoint updates are throttled and authoritative ball refreshes occur every 500 ms while held. The server checkpoints each accepted pose before publishing movement. `EndHeldBeam`, loss of the beam, warp, or leaving the bubble releases the object at its last committed pose. On release the server publishes a stationary ball with the source collision ID, scale, convex ID, surface type, and authored mini geometry restored; ship collision is enabled again. The independent object survives dungeon resets and server restarts; generated asteroid fields suppress the original asteroid ID while its detached record exists. Mineable asteroids retain their resource state under the new world ID and depletion removes that record.

Rebuild the generated Frontier game store after changing the source snapshot, then sync the generated static tables into the runtime game store through the normal deployment workflow. Patch or upgrade the build 3502403 staged client with `tools/frontier-client/frontier_windows_client.py`; the stage verifier reports `physicsGun: patched`. Existing installed runtime stores need the regenerated `itemTypes`, `typeDogma`, and `creationModules` tables before they can create or fit the item.

For an explicitly requested base-client update, run `python tools/frontier-client/frontier_windows_client.py sync-base --staged-root <stage>`. This copies the five verified stage overlay files (`code.ccp`, native `blue.pyd`, `manifest.dat`, and both CA bundles) into the recorded `stillness` source. The stage marker retains the original retail hashes, records the synced hashes and an original-file backup under `_local/frontier-client-source-backups/<build>`, and both the Python verifier and `StageFrontierClient.ps1` check the intentional sync. `PlayFrontier.ps1` continues to launch the staged client. Run `restore-base --staged-root <stage>` before a stage upgrade or `StageFrontierClient.ps1 -Clean`; after upgrading the stage, run `sync-base` again to update Stillness.
